# Measurement contract: implement before experiments
Required results.csv columns, in order:
request_id,scenario,source,start_time,first_token_ms,total_ms,status,retries,tokens_in,tokens_out,retrieval_setting,answer_grade
source: real or stand-in. status: ok, rate_limited, timeout, error.
answer_grade: correct, wrong, refused_correctly, refused_wrongly; leave blank for requests producing no assessable answer and report ungraded count. Do not assign fake refusal grades to transport failures. Grade citations and claim support, not fluency.

The brief's base schema cannot encode queue peaks, monetary costs, scenario duration, or provider-limit evidence. Preserve all required columns and ADD fields (document this reconciliation): run_id, question_id, model, pipeline_commit, config_hash, seed, scheduled_start_time, actual_send_time, offered_window_s, arrival_lag_ms, outcome_reason, queue_peak_observed, tokens_usage_complete, provider_first_token_ms, waiting_ms, working_ms, retry_wait_ms, answer_delivery_ms, cost_usd, cost_basis, limit_snapshot_json. Header/limit snapshots are JSON strings in CSV, from redacted real evidence. Identical run metadata may repeat per request so tables are reconstructible from this single file. No zero-request table scenario.

Also keep call-level JSONL (stage, attempt, model, status, usage, timestamps, redacted headers) and span/event JSONL (queue/gate/retrieval/call/retry/verification/delivery/cancel). Use UTC ISO start_time and monotonic elapsed clocks. Logs never contain API keys/Authorization. Count every failed attempt's known usage; mark unknown usage, never treat unknown as zero. Record tokenizer estimate separately from provider-reported usage. Record simulator clock/date and limit scope.

Timing policy: user first_token_ms is first checked content observed at client; blanks for no answer token. Provider TTFT separate. Time-to-terminal recorded for every request. Total-time table covers all terminal outcomes; TTFT covers delivered answers only, with denominator and failed/no-token counts shown. Also produce successful-total supplemental metrics for interpretation. Percentiles use one documented method (e.g. linear/numpy default); don't pretend p99 is reliable with tiny samples. Queue waiting, active work and retry wait intervals must partition total without overlaps/double counting; concurrent spans use union, not sums. Delivery duration recorded separately and classified consistently in working.

Arrival duration: configured scheduling window, not drain time. offered/min = sent count*60/window_s; record actual send lag and scheduling failure. Burst uses explicit nonzero window. Client abandonments -> timeout with outcome_reason=client_abandoned. Final rejected provider/admission quota -> rate_limited with reason. Retried 429 ending ok counts successful; record upstream_429_count separately. Every sent request appears once; no silently missing errors.

Tokens/answer: sum all input+output known tokens for the run (including failed attempts), divided by delivered answers, so waste is visible; separately report per-request tokens and unknown-usage count. Retrieval rows count all attempted questions, grade percentages divide by questions; report refused_wrongly and ungraded separately so missing categories aren't hidden. Correct+cited means correct grade only; correctly refused is distinct.
Cost: observed free-tier billed model cost is zero only if verified; label excludes infrastructure. Simulator actual billing is zero; hypothetical equivalent paid cost must be a separate field with timestamped price evidence. Never present assumed paid cost as measured. No delivered answers -> tokens/answer and cost/1000 answers undefined/not measured, not zero. Don't charge streamed cached text as newly generated tokens.

Limits: distinguish documented, account configured, header-advertised and empirically observed. request headers refer to RPD, token headers to TPM in Groq docs; verify current docs. Unknown concurrency is not an established ceiling. Do not intentionally exhaust a daily account budget just for a screenshot; simulate exhaustion, label empirical daily evidence not measured if absent. Limit-halving transition should happen mid-run at a recorded time and gate/provider state update together. Minute/day exhaustion tests must include in-flight and queued users.
